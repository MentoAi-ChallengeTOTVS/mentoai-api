# Banco de Dados

## 1. Objetivo

Este documento descreve o modelo relacional técnico do MentoAI e as convenções de persistência.

Banco alvo:

```text
Oracle Database
```

O schema atual possui 11 tabelas principais.

---

## 2. Estratégia de schema

A evolução do schema deve ser controlada por Flyway.

Diretório:

```text
src/main/resources/db/migration/
```

Primeira migration:

```text
V1__create_initial_schema.sql
```

Alterações futuras devem gerar novas migrations.

Exemplo:

```text
V2__add_example_field.sql
V3__create_example_index.sql
```

Não alterar migrations já aplicadas/compartilhadas para representar mudanças futuras.

### Hibernate

Hibernate deve mapear e validar o schema.

Configuração esperada:

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: validate
    open-in-view: false
```

Não utilizar `ddl-auto=update` como mecanismo oficial de evolução do banco.

---

## 3. Identificadores

As tabelas utilizam:

```sql
NUMBER(19) GENERATED BY DEFAULT AS IDENTITY
```

como estratégia de identificação.

No mapeamento JPA, a estratégia deve permanecer compatível com colunas Oracle Identity.

## 4. Tabelas

### CLIENTE

```text
ID       NUMBER(19)   PK
NOME     VARCHAR2(255) NOT NULL
SEGMENTO VARCHAR2(100) NOT NULL
PORTE    VARCHAR2(50)  NOT NULL
CRIACAO  TIMESTAMP     NOT NULL DEFAULT SYSTIMESTAMP
STATUS   NUMBER(1)     NOT NULL DEFAULT 1
```

Constraints:

```text
PK_CLIENTE
CK_CLIENTE_STATUS → STATUS IN (0,1)
```

Mapeamento conceitual:

```text
STATUS NUMBER(1) ↔ Boolean status
```

## 5. Relacionamentos

```text
CLIENTE.ID
    ← REUNIAO.CLIENTE_ID

USUARIO.ID
    ← REUNIAO.USUARIO_ID
    ← CHAT.USUARIO_ID
    ← ALERTA_USUARIO.USUARIO_ID

REUNIAO.ID
    ← TRANSCRICAO.REUNIAO_ID [UNIQUE]
    ← ANALISE_IA.REUNIAO_ID [UNIQUE]

ANALISE_IA.ID
    ← INSIGHT.ANALISE_ID
    ← SINAL_COMERCIAL.ANALISE_ID

SINAL_COMERCIAL.ID
    ← ALERTA.SINAL_COMERCIAL_ID [UNIQUE]

ALERTA.ID
    ← ALERTA_USUARIO.ALERTA_ID

CHAT.ID
    ← PERGUNTA_CHAT.CHAT_ID
```

Cardinalidades resultantes:

```text
Cliente         1:N    Reuniao
Usuario         1:N    Reuniao
Reuniao         1:0..1 Transcricao
Reuniao         1:0..1 AnaliseIA
AnaliseIA       1:N    Insight
AnaliseIA       1:N    SinalComercial
SinalComercial  1:0..1 Alerta
Alerta          1:N    AlertaUsuario
Usuario         1:N    AlertaUsuario
Usuario         1:N    Chat
Chat            1:N    PerguntaChat
```

## 6. Convenções JPA

- Domain Entity e JPA Entity são classes separadas.
- Enums devem ser persistidos como `STRING`.
- Não usar ordinal.
- Evitar relações bidirecionais desnecessárias.
- Preferir `LAZY` em associações.
- O lado correspondente à FK deve manter a referência JPA.
- O Domain não deve conter IDs de FK paralelos às referências de objetos apenas por causa do banco.

---

## 7. Fonte de verdade da persistência

Após adoção do Flyway, a fonte operacional do schema passa a ser:

```text
src/main/resources/db/migration/
```

Este documento deve acompanhar a estrutura relevante do schema, mas não substitui as migrations executáveis.
